## How to read this

- **Memory** is llama.cpp's own breakdown at startup (GPU + host buffers: weights, KV cache, compute), plus the vision encoder's file size for arms with figures. **Fits** compares it with ⅔ of the tier's RAM, what macOS lets the GPU use on an 8–32 GB machine. (The OS's own peak-memory figure is recorded in `arm.json` but undercounts: it leaves out the memory-mapped model file.)
- **Formulations found** = golden formulations paired with a predicted one, out of all golden formulations. Pairing is on anion + salt concentration (see `pipeline/evaluation/rowmatch.py`); *rank* pairings, made by concentration order when the paper and the golden set state concentration in different units, are counted in brackets. **Precision** = predicted formulations that paired, out of all predicted.
- **Accuracy** = correct cells out of the golden-filled cells *in paired rows*: when the model finds a formulation, how right is it. **Recall** = correct cells out of the golden-filled cells in *all* golden rows: a missed formulation costs every one of its cells.
- **Headline** pools the groups whose values a paper normally prints: identity, thermal, conductivity, transport, molecular_weight. `curator_computed` (SMILES, functional groups per monomer, the curators' own fits) is shown but never in the headline.
- **Conductivity** is right if within 0.1 decades of the golden value (about ±26%); *loose* allows 0.5 decades (about ×3), the realistic bar for a value read off a log-scale plot.
- A blank golden cell is never counted against a model. Cells the model filled where the golden set is blank are counted in `scores.json` as *extra*, not scored.
